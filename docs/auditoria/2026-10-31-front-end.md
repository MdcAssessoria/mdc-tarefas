**Data:** 31/10/2026. **Método:** leitura do código; `npx tsc --noEmit`; ESLint rodado só para leitura, com uma config temporária fora do projeto (veja A11); e buscas com grep para contar padrões. Nenhum arquivo do projeto foi alterado.

## Resumo executivo

1. O código é tipado (`strict`, nenhum `any`, `tsc` sem erros) e o vocabulário de domínio em português é consistente. A base é boa para refatorar.
2. O maior custo de manutenção é não ter camada de dados: 31 arquivos chamam o Supabase direto (172 `.from(`), há 94 casts `data as X` sem tipos gerados do banco e cerca de 11 gravações ignoram o erro.
3. Utilitários básicos estão duplicados e com comportamentos diferentes: três `brl`, oito formatações de data feitas à mão e um "hoje" calculado em UTC em mais de 10 lugares, embora `hojeISO(fuso)` já exista. Isso já gera bugs de data depois das 21h.
4. Quatro arquivos concentram responsabilidades demais (`config` 1145 linhas, `hub/acessos` 1302, `Painel.tsx` 651, `balancete.ts` 614). Além disso, a gestão de acessos do portal existe em duas telas, com listas de permissões copiadas.
5. Não há lint, formatação, testes nem CI. ESLint, Prettier e Vitest estão em `node_modules`, mas fora do `package.json`, então dá para adotá-los com atrito mínimo, começando pelos testes das funções puras de `balancete.ts`.

### A1. Não há camada de acesso a dados: Supabase espalhado, sem tipos do banco e com erros ignorados
- **Onde:** 31 arquivos (`app/**/page.tsx`, `components/AppShell.tsx`, `components/TarefaEditor.tsx`, `lib/*`).   - O padrão "`useCallback carregar` + `useEffect` + `setErro(traduzirErro(...))` + `data as T[]`" se repete em quase todas as páginas, com pequenas variações (umas param no primeiro erro, outras não).

  - Lotes não atômicos: `app/config/page.tsx:427-434` faz N `update` em sequência e para no primeiro erro, deixando metade aplicada; `app/hub/acessos/page.tsx:1050-1067` faz N RPCs em sequência com o mesmo problema.
- **Proposta:**
  1. Gerar os tipos: `supabase gen types typescript --project-id bulqqdgfrrpqquqvjjfa > src/lib/supabase/database.types.ts` (a pasta `../supabase/migrations` já existe) e usar `createClient<Database>(...)`. Os casts deixam de ser necessários aos poucos.

### A2. Bug: a notificação clicada nunca é marcada como lida
- **Onde:** `components/AppShell.tsx:579-582`
  ```tsx
  onClick={() =>
    !n.lida_em &&
    supabase().from("hub_notificacoes").update({ lida_em: new Date().toISOString() }).eq("id", n.id)
  }
  ```
- **Problema:** o `PostgrestBuilder` só faz o `fetch` dentro de `then()` (`node_modules/@supabase/postgrest-js/dist/index.mjs:393`). Sem `await` ou `.then()`, a requisição nunca sai. Esse tipo de erro só é pego com a regra `@typescript-eslint/no-floating-promises`.
- **Proposta:** `void supabase().from(...).update(...).eq("id", n.id).then(({ error }) => error && console.warn(error))`. Melhor ainda: mover para `dominios/notificacoes/api.ts → marcarLida(id)`. Ative `no-floating-promises` no lint (A11).
- **Esforço:** P. **Risco:** baixo.
